# 全库精读模式（Full-Library Reading）

> **来源**：一次真实项目的教训。某辩论报告完成"正文引用文献逐篇精读"后，
> 用户要求"精读**所有下载的全文**"。结果发现：106 篇中 84%（89 篇）此前从未进入论证，
> 而其中包含**改变论证结构的证据**——例如"IA 输注后细胞不入脑"的四条独立来源中，
> 有三条来自此前从未精读的文献。

---

## 一、为什么需要全库精读（而不只是精读引用的）

| 只精读引用文献 | 全库精读 |
|---|---|
| 引用错误的文献**查不出来**（因为根本没读它） | 所有下载的文献都经过核查 |
| 84% 的证据从未进入论证 | 全部证据纳入视野 |
| 低相关文献的误引无法预防 | 低相关文献也建立"负面清单"防误引 |
| 论证链基于"选中的证据" | 论证基于"全部证据" |

**关键洞察**：全库精读的目的**不是**让所有文献都进正文，而是：
1. 让**关键的遗漏证据**浮出水面（可能改变论证结构）；
2. 为所有未引用的文献建立**防误引负面清单**（明确"这篇不能用于什么"）。

---

## 二、何时触发全库精读

- 用户明确要求"精读所有下载的全文"；
- 证据库规模不大（≤150 篇）且已全部下载全文时，**建议直接全库精读**——成本与收益比优于"只精读引用的"；
- 证据库规模很大（>150 篇）时，至少应对**证据索引中标记"全文级"的全部文献**做轻量精读（见下"分层策略"）。

---

## 三、执行流程

### Step 1：批量提取全文（前置，无 Agent 参与）

```bash
cd <项目>/02_解析文本
for X in ../01_全文_JATS/*.xml; do
  P=$(basename "$X" .xml)
  [ -f "${P}_full.txt" ] || python extract_paper.py "$P"
done
```

**注意**：`extract_paper.py` 必须能提取表格——表格可能位于 `<floats-group>`（body 之外），
仅查 `<body>` 会漏掉 Table 3 这类核心数据。

### Step 2：按主题分批

先把待精读清单按主题聚类（IA 给药 / IC 移植 / 荟萃 / DTI 预测 / 外泌体 / 低相关），
每批 6 个 Agent 并行，每 Agent 3–4 篇。**低相关文献（心脏/兽医/材料/文献计量）单独成批**，
用批量模板快速处理，但**必须产出独立精读文件**——防误引的价值就在这里。

### Step 3：Agent 提示词（必须包含）

对**正文引用过的文献**：
- 报告引用它的**逐条上下文**（核查靶子）；
- 要求：完整通读后再动笔、禁止只读 grep 片段、主动报告"原文没说什么"、不得遗漏不利证据。

对**未引用过的文献**（全库精读的大头）：
- 判断"是否含有足以改变现有判决的关键数据"——若有，指出支持或反驳哪条判决；
- 判断"关联度"——低相关者须给出五维理由（适应症/细胞类型/给药途径/时窗/物种）；
- **建立防误引负面清单**：明确"这篇**不能**用于什么"（如"不可引用为卒中疗效证据"）。

### Step 4：提取修正清单

用脚本扫描全部精读文件第 7 节，提取所有针对报告的引用问题（🔴/🟠），
按"是否影响正文引用"筛选，形成修正清单。**328 个问题条目中，只有影响正文的才需要改报告，
其余进入负面清单备用。**

### Step 5：修正并保留痕迹

凡精读证伪的表述，**无论其结论对哪一方有利，一律更正**，并在报告保留修订痕迹：

```markdown
> **⚠️ v3 修正**：上一版此处写"..."。精读确认原文为"..."。结论方向[不变/反转]，论证依据[已更正/已更换]。
```

**修正不选择方向**：如果修正结果让"我方"三条管线都更差，那不是修正错了，而是**此前的乐观偏差在三个方向上都存在**——如实呈现。

---

## 四、分层策略（大证据库）

| 层级 | 范围 | 精读深度 |
|---|---|---|
| L1 全量 | 全部已下载全文（≤150 篇） | 完整八节（推荐） |
| L2 分级 | >150 篇时：正文引用 + 证据索引"全文级"标记 | 完整八节 |
| L3 轻量 | 其余 | 元数据核对 + 与判决的相关性判断 + 负面清单（约 30 分钟/篇，可 1 Agent 批量 6–8 篇） |

**无论哪一层，产出格式统一**（八节结构），保证后续可被脚本批量扫描。

---

## 五、全库精读后的必做动作

1. **更新"关键发现汇总"文件**——按证据强度排序，标记每条发现对判决的影响；
2. **更新报告头部**——记录精读范围与规模（篇数、判定统计 🔴🟠✅）；
3. **对"判决影响为零"的发现也要记录**——它们构成"已查证未使用"的证据基础；
4. **更新负面清单**——这是全库精读最重要的防误引产出。

---

## 六、全库精读的常见坑

| 坑 | 表现 | 对策 |
|---|---|---|
| 只精读正文引用 | 84% 证据未核查 | 触发条件见 §2 |
| 表格遗漏 | Table 3 这类核心数据没提取 | extract_paper.py 用 root 查找 table-wrap |
| Agent 只读 grep 片段 | 断章取义 | 提示词强制"完整通读后再动笔" |
| 低相关文献跳过 | 后续误引（TBI 当卒中） | 低相关也必须产出负面清单 |
| 修正选择方向 | 只改对"我方"不利的 | 铁律：证伪即改，无论对谁不利 |
| 引语只核方向不核逐字 | "scar/ECM" 引语不存在 | 关键引语必须 grep 全文确认逐字存在 |
